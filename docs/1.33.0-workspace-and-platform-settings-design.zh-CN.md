# SlimeBot 1.33.0 技术设计：会话工作目录与消息平台设置

状态：已实现，待交互验收。基线：`origin/main` 的 `a6cf3b3`。实现位于本地 `dev/1.33.0` 分支。

## 目标与边界

- Web 和桌面端可在输入框上方为**新聊天草稿**选择工作目录。发送首条消息并创建会话后目录锁定；进入任何已有会话都只能查看目录，不能切换。一个会话对应一个目录；文件、搜索、命令、沙箱及项目说明使用同一个目录。
- Web 侧边栏按项目目录分组。没有目录记录的历史会话放在「未分类」，不推测其来源，也不批量修改旧数据。
- CLI 仍以启动时的当前目录作为实际工作目录，不增加目录选择交互。新建 CLI 会话可以把该目录写入会话字段，便于 Web 按项目显示；旧 CLI 会话仍归「未分类」。
- 修复消息平台默认模型下拉框滚动即关闭，以及所选模型删除后仍保留失效 ID 的问题。

## 现状与关键问题

`domain.Session` 目前没有目录字段，`POST /api/sessions` 只接收名称，前端 `HomeSidebar` 按更新时间平铺会话。CLI 的 `RunContext.WorkingDir` 在启动时生成，Web 为空。聊天提示、沙箱和工具有不同的目录来源：项目 `AGENTS.md` 只在 CLI 读取；沙箱与 `exec`、文件工具的相对路径依赖服务进程的 `os.Getwd()`；Web 的 `grep/glob` 没有默认目录。直接调用 `os.Chdir` 会让并发会话互相干扰，不能采用。

`AppSelect` 把捕获阶段的全局 `scroll` 事件当成关闭条件，弹层本身滚动也会触发关闭。消息平台模型 ID 保存在设置表；删除模型或其提供商不会清理该设置。`ResolvePlatformModel` 在回退到全局/首个模型时又把回退 ID 写进设置，导致「未配置」无法稳定保持。

## 数据与接口

1. 在 `domain.Session` 加可空的 `workingDirectory`（数据库 `working_directory`，路径字符串；空值表示未分类）。GORM `AutoMigrate` 增列，历史行保持空值，无批量回填。
2. `POST /api/sessions` 增加可选 `workingDirectory`。服务端只接受服务器所在机器的**绝对目录**：清理路径、解析符号链接、确认存在且为目录，持久化规范化的绝对路径。拒绝文件、空目录名、相对路径与不可访问目录，返回明确的 4xx 错误；空字段保留兼容行为。Windows 使用本机路径规则处理盘符和大小写。
3. 列表与创建响应直接返回 `workingDirectory`，无需独立项目表。项目身份是规范化路径，而非文件夹名；同名目录分别成组，完整路径可在悬停提示中查看。列表仍按全局更新时间分页，前端对已加载结果分组；搜索仍走现有 `q`，不改变原有会话排序和分页语义。
4. 工作目录只允许在 `/chat/new_chat` 且尚未创建会话的草稿中选择。现有流程会在首次发送时调用 `POST /api/sessions`，此时把待选目录一并提交并持久化；无需新增修改目录的 `PATCH` 接口。首次发送期间隐藏项目选择栏；只要会话已创建，即使发送失败、消息尚未写入，也保持锁定，需要切换时新建聊天。打开任何已有会话不显示项目选择栏，旧会话即使没有目录记录，也不能事后归到某项目。已锁定目录被删除或移动时保留原路径标识，不自动换目录或落到服务目录。
5. CLI 创建新会话时传递启动目录；聊天运行仍从 CLI 启动目录取值，既有会话和 CLI 命令的目录识别不变。消息平台固定会话没有项目目录，单独显示在侧边栏顶部。

## 运行时目录传递

以会话 ID 查询 `workingDirectory`，在单次聊天请求上下文中传递目录；子代理沿用父会话目录。不得改进程级 cwd。对于未分类旧会话，保留原有运行行为，Web 不凭空指定项目目录。

- 系统提示：全局说明保留现有缓存；项目目录和项目 `AGENTS.md` 按会话生成动态段，避免 A 项目内容进入 B 项目的缓存。CLI 的启动目录继续走原有路径。项目技能目录不在本次范围内。
- 沙箱：`workspace-write` 的 CWD 使用当前会话目录；CLI 仍为启动目录。明确配置的 writable roots 与现有审批规则继续生效。
- 工具：`exec` 未给 `working_directory` 时以会话目录为默认；文件工具相对路径、`grep/glob` 空 `path`、工具审批信息也从请求上下文取目录。显式绝对路径仍按原有沙箱检查。对目录上下文做一个共用解析函数，避免各工具各自回退到服务进程 cwd。
- MCP 和后台任务若没有交互会话目录，继续现有行为。任何需要项目目录的调用应显式传递会话上下文，不能依赖全局变量。

## Web / Desktop 交互

参考图（用户提供，红框为输入框上方的项目上下文位置）：

![Codex 输入框上方的项目上下文栏示例](1.33.0-workspace-reference.png)

SlimeBot 采用图中这种位于输入框上方、与输入框分开的单行项目栏：文件夹图标、项目名、`本地` 标识，以及所在 Git 仓库的当前分支。完整绝对路径放在悬停提示和选择器中，不在窄栏里挤压输入框。项目栏只在新聊天草稿显示；桌面端点击即通过 Electron IPC 打开系统文件夹选择器，并从上次目录开始。浏览器端点击打开服务端目录选择窗口，提供主目录、桌面、文档、下载、项目、OneDrive（若实际存在）及最近目录，支持逐级浏览和绝对路径跳转。常用位置只显示实际存在的目录；Linux 尊重 XDG 用户目录配置，Windows 支持 OneDrive 位置。浏览器无法取得客户端电脑的绝对路径，因此窗口明确标注它选择的是 **SlimeBot 服务端机器**上的目录。已有会话隐藏项目栏。

新聊天从某项目分组的「新建会话」入口进入时预选该目录；侧边栏顶端的通用新建入口沿用上次使用的目录。该待选值只存于草稿状态，提交后由后端返回的规范化路径成为唯一来源。已有会话和旧的未分类会话都隐藏项目选择栏。草稿选择目录时无需在侧边栏生成会话，首次发送后才进入对应项目分组。无目录的新聊天显示「选择工作目录」，仍允许按旧行为聊天。

侧边栏保留消息平台入口在顶部，下面按目录分组，最后显示「未分类」。项目标题可折叠，只显示文件夹名；完整路径在鼠标悬停提示中显示，同名目录仍以完整路径作为不同分组键。项目名使用比会话列表更醒目的字号和字重，文件夹图标同步放大。组内会话缩进并沿细引导线排列，组间用紧凑留白区分；悬停显示轻底色，选中的会话用更明确的品牌色底色和左侧标记，项目标题不随会话选中而变色。组内按 `updatedAt` 倒序，默认显示前 6 条，通过「显示更多」逐批展开；项目折叠后重新展开时恢复前 6 条。点击搜索按钮不改变当前项目展开状态，输入关键词后展开匹配组并显示全部匹配结果。滚动加载继续使用现有全局分页，只有接口确认存在下一页时才显示列表底部的「加载更多会话」入口，后续页合并到对应组。浅色/深色主题沿用现有设计 token；目录栏和选择器要有清晰 hover、focus、选中态，并支持 Esc 关闭及键盘操作。

## 两个设置修复

1. `AppSelect` 的全局滚动处理区分弹层内部滚动与外部滚动：弹层内滚轮、触控板滚动不关闭；外层容器滚动时重新计算定位或关闭。点击选项、外部点击、Esc 的行为保持一致。对消息平台默认模型的长列表验证鼠标和滚轮均可选择。
2. 在删除模型、删除提供商所关联模型的数据库事务中，如果保存的 `messagePlatformDefaultModel` 指向被删 ID，就写入空字符串。设置读取时对升级前遗留的失效 ID 也返回空字符串。`ResolvePlatformModel` 仍按「显式设置 → 全局默认 → 首个可用模型」计算**本次运行的有效模型**，但不把回退 ID 写回消息平台设置；显式选择「未配置」会一直保持。模型列表刷新后前端同步显示空值，避免已打开的设置面板保留旧标签。现有 30 秒模型缓存须在设置变更时失效，或移除缓存，确保新选择及时生效。

## 验收

- 数据迁移后，旧会话原样可读且在「未分类」；新 Web/CLI 会话按目录分组，两个同名目录不会合并；搜索与分页不漏会话。
- 新聊天草稿可反复选择目录；首次发送开始后以及任何已有会话中都不能切换。发送失败但会话已创建时仍锁定；刷新页面、切换会话后也不能重新归类。旧会话保持未分类。
- 两个并发会话各自在不同目录运行文件读写、`exec`、`grep/glob`，沙箱和项目 `AGENTS.md` 都严格使用各自目录；CLI 仍使用启动目录。目录不存在时给出明确错误，不落到服务进程目录。
- 桌面系统文件夹选择器与 Web 服务端目录选择窗口可用；输入框上下两个布局、移动端宽度、浅色/深色主题、键盘焦点均检查。
- 消息平台长模型列表在滚轮及点击时不消失；删除选中模型或其提供商后显示「未配置」，重启后仍如此，消息平台实际发送仍能按运行时回退策略选择可用模型。
- 实现后运行 `go test ./...`、`npm --prefix frontend test`、`npm --prefix cli test`，并进行 Web/桌面手动交互验收。

## 建议实施顺序

先完成会话字段、接口和 CLI 记录路径；再打通请求级目录、沙箱与各工具；随后实现输入框目录栏和侧边栏分组；最后修复下拉框与模型失效，并做跨端回归。目录相关单测以并发隔离、旧数据迁移和路径校验为重点，避免只验证组件渲染。
